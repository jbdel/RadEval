# Changelog: 2026-07-08 — CT head/neck LLM-as-a-Judge metrics (sv001)

**Branch**: `feat/f1hoppr-cth-rrg-lv001-cls-lv003` → PR into `hopprai/radeval:main`.

## Summary

Two new **private**, Gemini-backed LLM-as-a-Judge metrics for CT head/neck
reports, scoring two complementary axes over a fixed closed set of 10 findings
(Atrophy, White Matter Disease, Sinus Disease, Post-Surgical Calvarium,
Intracranial Atherosclerosis, Lens Replacement, Scleral Buckle, Technical
Limitation, Encephalomalacia, Mastoid Effusion):

- **`hoppr_crimson_cth_sv001`** — factual-correctness (presence axis). Extracts
  present/uncertain findings from both reports, matches them, classifies
  false_findings / missing_findings / presence_state_mismatches, and scores with
  the CRIMSON `(-1, 1]` formula weighted by per-finding clinical significance.
- **`hoppr_modifier_cth_sv001`** — modifier accuracy. On findings *both* reports
  agree are present, scores only the non-presence modifiers (severity,
  localization, laterality, region, sinus subsite) as micro-averaged
  correct/total slots in `[0, 1]`. Presence is deliberately excluded (owned by
  the CRIMSON-style metric) so presence errors are never double-counted.

The `_sv001` suffix is a score-version tag: a new prompt/rubric version becomes
`_sv002`, etc.

## Design

- Both built on `LLMMetricBase` (single call per (ref, hyp) pair) mirroring
  `MammoGREEN`. Default provider `gemini`, model `gemini-3.1-flash-lite`,
  temperature 0, JSON response (`responseMimeType="application/json"`). OpenAI is
  also supported via `SUPPORTED_PROVIDERS = {"openai", "gemini"}`.
- Shared schema lives in
  `radeval/metrics/hoppr_crimson_cth_sv001/cth_schema.py` (the 10 findings, the
  per-finding modifier map, severity-normalization rules, and verbatim clinical
  definitions). The modifier metric imports it from the sibling folder; both are
  stripped together on publish.
- Failure-mode support: each scorer retains a per-sample `results_df` and exposes
  `error_totals()`. `detailed=True` surfaces summed per-error-type counts as
  extra scalar keys (e.g. `hoppr_crimson_cth_sv001_total_missing_findings`,
  `hoppr_modifier_cth_sv001_total_severity_errors`).

  are intentionally absent there, matching `hoppr_crimson_ct` etc.).
